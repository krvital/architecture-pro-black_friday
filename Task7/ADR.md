# MP-ADR4 Проектирование коллекций MongoDB
**Дата:** 20.02.2026

**Автор:** Виталий Кравцов

### Контекст
Онлайн-магазин «Мобильный мир» сильно вырос, и теперь там можно купить не только аксессуары для смартфонов, но также электронику, аудио- и бытовую технику и другие категории товаров. Однако бэкенд сайта всё так же состоит из нескольких микросервисов.

«Мобильный мир» хранит информацию о заказах, товарах и корзинах в трёх коллекциях в MongoDB. 

В системе используются три основные коллекции:

- `orders` — заказы пользователей
- `products` — каталог товаров
- `carts` — корзины пользователей и гостей

С увеличением объёма данных и нагрузки требуется внедрить шардирование MongoDB.

### Решение

Для каждой коллекции выбрана стратегия шардирования, оптимизированная под основные операции системы.

#### Коллекция `orders`

##### Схема документа:

```json
{
  "_id": ObjectId,
  "user_id": ObjectId,
  "created_at": Date,
  "status": "created | paid | shipped | delivered | cancelled",
  "geo_zone": "moscow",
  "items": [
    {
      "product_id": ObjectId,
      "price": Decimal128,
      "quantity": Integer
    }
  ],
  "total_sum": Decimal128
}
```

##### Основные операции:

- Быстрое создание заказов с одновременным списанием остатков.

- Поиск истории заказов конкретного пользователя.

- Отображение статуса заказа.

##### Выбор шард-ключа:

`{ user_id: "hashed" }`

- высокая кардинальность `user_id`  
- `hashed` обеспечивает равномерное распределение
- большинство запросов выполняются по пользователю



#### Коллекция `products`

```json
{
  "_id": ObjectId,
  "name": String,
  "category": String,
  "price": Decimal128,
  "attributes": Object,
  "stock": {
    "moscow": Integer,
    "kaliningrad": Integer
  }
}
```

##### Основные операции:

- Частые обновления остатков при покупках.

- Поиск товаров по категориям и фильтрация по диапазону цен.

- Описание товара на странице продукта.

##### Выбор шард-ключа:

`{ _id: "hashed" }`

- высокая кардинальность `_id` 
- `hashed` обеспечивает равномерное распределение
- операции обновления выполняются по `_id`



#### Коллекция `carts`

```json
{
  "_id": ObjectId,
  "user_id": ObjectId,
  "session_id": String,
  "owner_key": String,
  "items": [
    {
      "product_id": ObjectId,
      "quantity": Integer
    }
  ],
  "status": "active | ordered | abandoned",
  "created_at": Date,
  "updated_at": Date,
  "expires_at": Date
}
```

##### Основные операции:

- Создание корзины, когда заходит гость или новый пользователь. Получение текущей корзины по фильтру { session_id, status:"active" } или { user_id, status:"active" }.

- Добавление или замена товара в корзине.

- Удаление товара из корзины.

- Слияние гостевой корзины в пользовательскую, если пользователь залогинится: 

  - прочитать гостевую { session_id, status:"active" };

  - добавить её items в корзину { user_id, status:"active" };

  - отметить гостевую как abandoned.

- Отметка корзины как заказанной.

##### Выбор шард-ключа:

`{ owner_key: "hashed" }` для ключа `owner_key`, который в случае гостем будет заполен значением из `session_id`, а в случае с пользователем из `user_id`

- высокая кардинальность `_id` 
- хорошо подходит как для операций с `session_id` так и `user_id`

# MP-ADR6 Стратегия чтения из реплик для коллекций продуктов, заказов и корзин
**Дата:** 10.03.2026

**Автор:** Виталий Кравцов

### Контекст
Система использует MongoDB с шардированием и репликацией. Для повышения производительности и снижения нагрузки на primary реплики, некоторые операции чтения могут выполняться с secondary.

Необходимо определить:

- Какие операции чтения могут использовать secondary реплику
- Какие операции должны читать только с primary
- Допустимую задержку репликации для операций на secondary
- Обоснование выбора с точки зрения консистентности данных, частоты обновлений и бизнес-логики

### Решение

#### Таблица операций чтения

| Коллекция | Операция                                                   | Primary / Secondary | Допустимая задержка репликации | Обоснование                                                  |
| --------- | ---------------------------------------------------------- | ------------------- | ------------------------------ | ------------------------------------------------------------ |
| orders    | Создание заказа с одновременным списанием остатков         | Primary             | 0–100 мс                       | Актуальность критична, чтобы не продать недоступный товар и корректно списать stock. |
| orders    | Поиск истории заказов пользователя                         | Secondary           | 1–5 с                          | История может быть слегка устаревшей, риск бизнес-проблем низкий. |
| orders    | Отображение статуса нового заказа                          | Primary             | 0–100 мс                       | Нужно подтверждение пользователю актуального статуса заказа. |
| products  | Частые обновления остатков при покупках                    | Primary             | 0–100 мс                       | Stock должен быть актуальным при оформлении заказа.          |
| products  | Поиск товаров по категориям / фильтрация по цене           | Secondary           | 1–2 с                          | Каталог обновляется редко, небольшая задержка допустима.     |
| products  | Просмотр описания товара на странице продукта              | Secondary           | 1–2 с                          | Описание товара редко меняется, можно читать с реплики.      |
| carts     | Создание корзины (гость / новый пользователь)              | Primary             | 0–100 мс                       | Данные создаются и обновляются активно, нужна строгая консистентность. |
| carts     | Получение текущей корзины ({ session_id } или { user_id }) | Primary             | 0–100 мс                       | Критично видеть актуальные позиции и статус корзины.         |
| carts     | Добавление / замена товара в корзине                       | Primary             | 0–100 мс                       | Актуальность необходима для правильного подсчета quantity и сумм. |
| carts     | Удаление товара из корзины                                 | Primary             | 0–100 мс                       | Критично для корректности корзины.                           |
| carts     | Слияние гостевой корзины в пользовательскую                | Primary             | 0–100 мс                       | Нужно прочитать актуальную гостевую корзину и корректно обновить пользовательскую. |
| carts     | Отметка корзины как заказанной                             | Primary             | 0–100 мс                       | Обновление состояния корзины должно быть синхронным с order creation. |

#### Обоснование

**Частота обновлений**

- `orders` и `carts` активно изменяются, поэтому большинство операций должны идти на primary.
- `products` обновляется реже, поэтому поиск товаров, описание можно читать с реплики.
